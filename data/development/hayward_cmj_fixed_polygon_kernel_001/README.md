# Existing fixed-polygon kernel benchmark

This is a source/preparation-only diagnostic until a hash-bound root review authorizes execution. It evaluates the exact saved face, accepted first-step, rejected full second-step and accepted half-step polygons for native events 981 and 987 at receiver 160. It does not trace, initialize a field, optimize, resample, move a knot, evaluate source/model partials, integrate new reference bounds or compute normal support moments. Original false ray flags and blank source partials remain unchanged.

The earlier `hayward_cmj_saved_gradient_001` package already reproduced the ordinary gradients of the original old/D polygons. The earlier `loma_trial_accumulation_001` package measured original and extended segment arithmetic on the 24 recorded Loma trials. Neither evaluated these eight newer CMJ polygons. This batch reuses their actual `path_eval`/`segment` and paired-accumulation patterns without repeating those controls or changing the quadrature.

`source/core.hpp` is a byte-exact copy of the D kernel adopted on the integration branch; it has not replaced main's production or live retry binaries. `segment()` and all preceding sampling definitions are byte-identical to the retry's frozen old `7111f67c…` kernel. `path_eval()` differs only in its outer `double`→`long double` accumulator and still returns binary64; free-knot gradient arithmetic is identical. Thus the separately emitted `ordinary_sum` measures the old path action on exactly the same segment values. The D curvature helper is copied only as a compile dependency; no optimizer calls it here. The copied headers and recorded function bridge remain separate from live binaries and maintained sources.

The single C++ invocation makes eight `path_eval` calls and 8,232 additional `segment` calls to expose individual action values. It verifies each actual path action equals the cast of the extended sum of those same segment values. It records each free-knot gradient, all edge actions, ordinary and extended totals, and paired extended differences for first→second and first→half. Both pair tests use the second-step saved direction; the half case changes only the saved trial and alpha. The Armijo coefficient is the exact value of binary64 `1e-4`, matching the saved oracle's declared coefficient. There is no line search or acceptance of a new path.

The stdlib comparison uses only completed, independently reviewed reference records. All eight polygons have full/per-edge action bounds. Available derivative bounds exist for face and accepted first geometry; the rejected second geometry has no derivative oracle. Half-step derivative bounds remain explicitly unavailable in this frozen roster. Unavailable normal components are reported separately and never treated as ordinary smooth derivatives. The direction has exact zero entries there, so its slope is fully covered by the available components.

Every computed numerical action, gradient and slope value has an exact hexadecimal token; elapsed timings are decimal observations. The comparison parses hexadecimal significands and exponents directly to rational values, including wider-than-binary64 results, and normalizes signed-zero spelling for round-trip checks. It reports error intervals and distance from each saved enclosure, not an invented accuracy cutoff. Exact sums of the exported binary64 edges separately expose outer accumulation error. Unit rejection and half acceptance are compared using both the saved enclosed slope and the computed C++ slope; disagreements are preserved rather than turned into a failed data-loading gate.

The driver times each `path_eval` call without output I/O. Extra edge-check timing includes its CSV writes and is labeled accordingly. A single eight-polygon batch is a diagnostic cost observation, not a general performance benchmark. Large ordinary normal gradients at a grid-plane kink are not evidence of quadrature error; passing this benchmark would not certify stationarity, endpoint-derivative accuracy, first arrival or inversion success.

All inputs and outputs carry native context sidecars, including both events/origins, empty-location channel identity and epoch, original status and all nine catalog uses per ray. The current failed-trial model, endpoint coordinates, node order and topology are preserved. Run logs remain outside the frozen source/input inventory while open; terminal logs and output hashes are recorded only after child reaping.
