# Exact partition and explicit-cell segment diagnostic

This source-only package tests a separate fixed-segment evaluator on nine invented cases. The frozen original kernel is retained unchanged and called on the same inputs. The copied header includes integration D changes, but its segment body is byte-identical to the historical old kernel; no path accumulator or optimizer is exercised. No maintained source, native geometry, ray trace, FMM field, inversion, optimizer or stopping rule is changed. The [contact controls](../internal_face_contact_controls_001/RESULTS.md) preserve the original near-cut failures; this diagnostic does not overwrite or relabel them.

For endpoints `a,b`, let `d=b-a`, `L=|d|`, and `s=1/v`. The segment action and ordinary continuous endpoint variations are

```text
T   = L integral_0^1 s(a+t d) dt
G_a = -(d/L) integral s dt + L integral (1-t) grad(s) dt
G_b =  (d/L) integral s dt + L integral t grad(s) dt.
```

Python promotes the binary64 endpoints, grid planes and nodal velocities exactly to rational values. It sorts all true interior plane intersections without displacement or endpoint tolerances, groups equal intersections exactly, and selects each open interval's cell from its exact midpoint. A whole segment aligned with an internal plane has an unavailable ordinary normal derivative; the diagnostic reports that component as null, not zero or a stationarity claim.

The separate C++ evaluator retains the eight Gauss nodes/weights and the original binary64 length. Python supplies each piece's explicit cell, separately rounded positive width/scaled Gauss weights, global endpoint shape values, and local trilinear basis values. Cell selection never uses a rounded global sample coordinate. Local weights may round to zero or one and quadrature locations may coincide after rounding; those are permitted, while the exact selected cell remains fixed. Nonfinite arithmetic, a nonpositive represented piece/quadrature weight or total length, and out-of-roster geometry are rejected.

This is a **combined arithmetic change**: exact rational partitioning and sampling preparation, explicit cell selection, separately rounded endpoint/local basis weights and their stated summation order. It is not a patch that merely removes the old cut thresholds, nor an assertion that these quadrature gradient values differentiate the finite floating-point quadrature sum. The values approximate the displayed continuous first variations. The finite roster also requires each represented binary64 displacement to equal the exact endpoint difference; this is not a general input certificate.

The nine cases are the previous four displacement/endpoint-cut examples, the ridge translated to `c=1` with endpoints `nextafter(1,0)` and `nextafter(1,2)`, its reversal, a constant-velocity segment, an aligned segment with unavailable normal component, and a genuine trilinear velocity `v=(2+x)(3+y)(4+z)`. The translated case exposes rounded-sample cell selection near a nonzero face, but its old evaluator also omits the crossing through the displacement cutoff. Improvement in this combined variant therefore does not isolate either mechanism. Saved exact cells and rounded global sample coordinates allow a separate readback count of cell mismatches without another evaluator call. These coordinates belong to the exact-partition handoff; they are not an instrumented trace of the old evaluator's different quadrature samples. References are seven independent affine/log evaluations (series parameter 16, length bounds at 192 bits), one homogeneous closed form, and one existing rational trilinear evaluation at series degree 16 (17 retained powers), four subdivisions and 192 bound bits. The original four cases also require exact numeric equality of their old action, six endpoint components and reconstructed cuts, and exact geometry equality, with the preserved prior contact summary. All action/component error intervals are retained; there is no invented accuracy cutoff or native generalization claim.

The declared finite work is one compilation, nine helper calls, nine original segment calls and nine separate explicit-cell calls, with 17 pieces / 136 Gauss samples. The copied controller retains the reviewed signal-mask restoration and process-group termination/reaping behavior; only its scope text changes. The root agent owns the outer tool and keeps open outer logs outside this package. No execution is permitted before the frozen preparation and source review are accepted.

`source_mapping.json` records every byte-exact copied dependency and the controller's scope-only change. The eventual `prepared.json` records commands, source/runtime pins and the exact roster/budgets. A fresh `results/` will retain complete rational-to-binary64 handoff records, old and new values/hex, reference bounds and all errors; the original control package remains immutable.
