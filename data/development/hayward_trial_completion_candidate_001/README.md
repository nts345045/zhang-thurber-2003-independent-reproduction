# Prospective trial completion review

This is an isolated, unexecuted completion-review patch. `before/` preserves the current launcher; `after/` adds one saved-table helper and calls it after a successful inverse child. No maintained source, eligibility decision, frozen run, numerical kernel, configuration, ray or inverse is changed. The Python files have been parsed for syntax only. Malformed-input controls and independent source review must precede adoption.

The existing launcher checks final event/grid/native residual inventories, current-iteration history flags and the absence of `dd_failed_forward*`. It does not inspect candidate003's new `dd_rejected_trial_it_*` and `dd_iteration_*` records. Mixed or unexpected trial failures can leave the new prefix too; therefore simply allowing those filenames would be insufficient.

The proposed helper checks one trial ledger for each history/matrix iteration, the actual stage progression and existing twelve fractions, and the existing nonincrease criterion. An `accepted` ledger entry means only that the fixed-weight objective passed. It must be last and agree with the serialized history fraction/objective. Rejected and invalid-model rows must have no objective value. Quality rejection without any evaluable trial cannot be called completed. No requirement for strict improvement, LSQR convergence or a new gradient magnitude is added.

Each retriable row requires all eight identified rejection files. Its status table must cover the complete original observation support, including omitted rows and both native receiver epochs. All event/station metadata are joined, including empty locations, source hashes and any additional native columns. The failure roster must equal the status rows whose existing local flag is false, with the sole exact reason `local_stopping_failed`. Finite/domain/endpoint/initializer flags and unrequested derivative fields are checked without a new accuracy tolerance. Failed polygons are streamed in exact event/receiver/node order; coordinates, native metadata, counts, endpoints and finite-box membership are read back. No path is retraced.

Each iteration containing a quality rejection also requires the five first-rejection solve files. The reviewer checks all original source/model column indices, increments and reference values, LSQR/history links, declared weights/objective basis, and every original observation metadata field under `original_`. It retains every original residual and fixed multiplier, including omitted rows. These residuals and multipliers are not independently recomputed from unavailable current-model rays. The rejected states are reconstructed from that iteration's saved accepted state and original increment, using the unchanged clamping and exponential velocity update; no increment is inferred from a clamped trial. These exact binary64/17-digit joins are serialization checks, not new scientific accuracy thresholds. The executable/runtime pins still have to match the reviewed build. History uses the actual 12-digit display convention.

Only filenames computed from the validated iteration/trial indices are opened. An archived ledger's recorded absolute prefix is retained as evidence; only its exact basename is used for the join, and traversal components are rejected. Exact file inventory rejects orphan ledgers, solve files, rejection records and stale last-accepted files. The conventional last-accepted pair must be byte-identical to the last rejection's corresponding pair. All consumed files are hashed before and after the saved readback. Partial/fatal runs remain preserved by the existing controller exception path and cannot pass this completion review.

The helper does not reconstruct every accepted intermediate model: all-valid iterations have no solve snapshot in candidate003. It validates saved rejected states and their associated accepted states. Final output identity/domain checks remain in the launcher. Candidate003's full final gate runs before final outputs, but an all-success final gate emits no standalone full ray table. Consequently the patch binds one successful child return and the exact audited main hash to that gate and explicitly reports `independent_final_ray_table=false`. Final refinement/source checks and scientific review remain required; this is neither first-arrival certification nor a convergence result.

## Eligibility remains separate

`reviewed_inputs`, `REVIEWED_GUARD_MAIN`, initial scientific limits, inherited configuration and source-adoption checks are unchanged. This completion-only patch is intentionally **not launch-ready**: the current eligibility gate admits the previous main, whereas this completion checker requires exact candidate003 main `a10dcdc3…`.

The separately proposed bridge is the exact old7111 mathematical kernel/CMake/source cohort from the reviewed Hayward004 preflight plus candidate003's main-only control-flow change. It needs its own complete source inventory, actual-loop before/after O3 controls, updated guard/core/external controls and independent source-adoption review. A bridge must explicitly show which preflight numerical evidence remains applicable. It must not silently substitute maintained D headers. If kernels, forward configuration, identities or support differ beyond a justified reviewed bridge, fresh matching initial-cohort numerical validation is necessary before an inverse attempt. This package changes none of those requirements.

## Bounded controls to review before execution

Use the completed invented actual-loop files as saved-table fixtures; no ray call is needed. Accept intact all-valid and quality-then-accepted records. Then independently remove/duplicate/reorder ledgers or native rows, insert an orphan prefix, remove one of the eight/five files, change a reason or flag, alter either receiver epoch or an original metadata cell, change a delta/reference/clamped state, truncate a polygon, invent a rejected objective, change an acceptance inequality/history link, and stale the conventional accepted pair. Preserve each failed fixture. Exercise empty tables, invalid integers, symlinks and a nonzero/missing child result. A separate existing all-valid launcher fixture should still be checked after the exact source bridge is established; its earlier completion record is not retrospectively relabeled.

`prepared.json` pins this proposal, both launcher copies, helper, patch and the reviewed candidate/control source evidence. No compiler, controller or numerical execution was performed for this package.
