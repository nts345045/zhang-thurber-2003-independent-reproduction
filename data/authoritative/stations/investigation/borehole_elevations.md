# Borehole channel elevations

The evidence supports using the current NCEDC **provider-declared sensor elevations** for NC.CCH1, NC.CGP1, and NC.CSU1 without subtracting burial depth again. The equal Station/Elevation and Channel/Elevation values do not establish a ground-elevation convention. Conflicting annual-report tables remain a documented limitation; the investigation does not provide an independent sensor survey or resolve every vertical-datum statement.

| Station (derived FDSN station ID) | NCEDC channel and station elevation (m) | Channel burial depth (m) | Channel elevation + depth (m) | BSL 2005–2006 wellhead (m) | BSL 2013 wellhead (m) |
| --- | ---: | ---: | ---: | ---: | ---: |
| NC.CCH1 (FDSN:NC_CCH1) | 107 | 119 | 226 | 226 | 345 |
| NC.CGP1 (FDSN:NC_CGP1) | 219 | 121 | 340 | 340 | 461 |
| NC.CSU1 (FDSN:NC_CSU1) | 375 | 124 | 499 | 499 | 623 |

FDSN defines Channel/Elevation as sensor elevation and states that adding Depth gives ground elevation. Applied literally, positive-down coordinates are −0.107, −0.219, and −0.375 km in the provider's elevation datum. An additional subtraction of burial depth would change the receiver position by 119–124 m without support from this definition. [FDSN StationXML reference, §§2.4.8–2.4.9](https://docs.fdsn.org/projects/stationxml/en/latest/reference.html#elevation-required).

The earlier BSL table explicitly labels its elevations as wellhead elevations relative to the WGS84 ellipsoid. Subtracting the present channel depths reproduces the present Channel/Elevation values exactly. The later table retains that wellhead interpretation but increases all three numbers by exactly one burial depth. This is an actual disagreement between published wellhead tables. Neither table documents a corresponding station move or an explanation for these changes. It does not establish that the current XML sensor elevations are wrong. [BSL 2005–2006, Table 6.1, printed p.118, PDF p.125](https://www.ncedc.org/pub/annual_report/ar05_06.pdf); [BSL 2013, Table 4.3.2, printed p.111, PDF p.119](https://seismo.berkeley.edu/archive/2013_Annual_Report-archived.pdf).

The current NCSN master history also exposes the same numeric elevations, 107, 219, and 375 m, for these stations' historical channel records. This is another provider representation, not an independent survey. Its format describes ELEV in meters and flags these records with E, meaning an external telemetry GPS antenna. It does not state whether a borehole correction has already been incorporated into ELEV. The history therefore supports numerical consistency but does not establish a second burial correction. [Master station history](https://ncedc.org/pub/doc/ncsn/ncsn.stations); [format documentation](https://ncedc.org/pub/doc/ncsn/README.ncsn.stations).

NCEDC's legacy Channel_Data schema defines elevation relative to mean sea level and instrument emplacement depth relative to that elevation. The public FDSN service documentation does not explain whether the exporter transforms those database fields. These legacy definitions establish an additional convention to investigate, but they do not demonstrate that the current Channel/Elevation violates its declared FDSN meaning. [NCEDC channel schema](https://ncedc.org/db/Documents/NewSchemas/IR/v1.5.2/IR.1.5.2/Model1/Tbl3.htm); [NCEDC FDSN service documentation](https://service.ncedc.org/fdsnws/station/help/index.html).

The datum labels must remain explicit. The annual reports say WGS84 ellipsoid; NCEDC's 2015 explanation says station elevations and catalog depths use the same geoid datum. Those terms are not interchangeable. The preserved USGS terrain queries at the exact channel coordinates return 268.6456, 372.5852, and 532.8044 m. Their NAVD88 interpretation is not a conversion to either report's stated datum, and terrain height is not a sensor survey. These queries do not justify replacing the channel elevations. Use the NCEDC shared-datum convention as a provider assumption, with the report discrepancy retained. [NCEDC depth-datum explanation](https://ncedc.org/blog/2015/10/07/the-ncss-now-reports-earthquake.html); local [terrain acquisition](terrain_check.py) and its three `terrain_usgs_NC_*.json` responses.

This evidence does **not require blocking** use of these three channels merely because Station/Elevation equals Channel/Elevation. A suitable status is *provider-declared sensor elevation; conflicting published wellhead values documented*. It would be inaccurate to label the elevations independently verified or the datum conflict fully resolved. NC.CMW1 is outside this conclusion; its historical identities and remaining vertical interpretation are covered in [the CMW1 report](cmw1_report.md).

Raw official documents, including failed HTTP responses, are retained unchanged in [borehole/](borehole/), with URLs, retrieval times, hashes, and identifier sidecars. [The channel snapshot](borehole/channel_epoch_snapshot.csv) preserves all 30 cached channel epochs, valid empty locations, FDSN identifiers, and original XML source hashes. [The historical extract](borehole/historical_station_rows.csv) preserves 33 exact source lines and their NSLC identities and operation epochs. The snapshot retains the pre-investigation ambiguity flags; it is evidence, not a repaired solver input. No acquisition code, channel table, selections, or solver coordinates were changed here.
